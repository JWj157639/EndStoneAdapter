> 本文档记录废弃的 `HuhobotClient` 中发现的错误码和状态码，供新代码参考。

### 配置来源说明

根据官方协议文档，配置项来源如下：

| 配置项 | 来源 | 说明 |
|--------|------|------|
| `serverId` | 服务端下发 | 通过 `sendConfig` 事件获取，保存到配置文件 |
| `hashKey` | 服务端下发 | 通过 `sendConfig` 事件获取，保存到配置文件，用于下一次握手 |
| `serverName` | 本地配置 | 用户在 `config.json` 中设置 |
| `version` | 本地生成 | 通过 `HuHoBot::getVersion()` 获取 |
| `platform` | 本地生成 | 固定值 `"endstone"` |

**重要**：`serverId` 和 `hashKey` 是由服务端下发的，不是本地生成的。客户端首次连接时这两个字段为空，服务端会通过 `sendConfig` 事件下发配置，客户端保存后重新连接握手。

## 重连状态

| 场景 | 日志信息 | 处理方式 |
|------|----------|----------|
| 连接丢失 | "WebSocket连接丢失:{code}" | 创建重连任务 |
| 重连中 | "正在尝试重新连接,这是第({current}/{max})次连接" | 递增重连计数 |
| 重连失败 | "重连失败: {exception}" | 标记需要重连，创建重连任务 |
| 达到最大次数 | "重连尝试已达到最大次数，将不再尝试重新连接" | 取消重连任务 |
| 服务端强制断开 | "服务端命令断开连接 原因:{msg}" | 设置 `shouldReconnect = false`，关闭连接 |

## 错误处理场景

### 消息解析错误
- **JSON 解析失败**: `logger->error("消息解析失败: {}", e.what())`
- **消息处理异常**: `logger->error("消息处理异常: {}", e.what())`
- **未知事件类型**: `logger->error("未知事件类型:{}", type_str)`

### WebSocket 错误
- **连接错误**: `logger->error("WebSocket错误:{}", errorMsg)` - 仅记录日志，不触发重连
- **连接丢失**: `logger->error("WebSocket连接丢失:{}", code)` - 触发重连

### 业务逻辑错误
- **在线查询失败**: `logger->error("处理在线查询失败: {}", e.what())`
- **白名单查询失败**: `logger->error("查询白名单失败: {}", e.what())`
- **命令执行失败**: `logger->error("命令执行失败: {}", e.what())`
- **命令参数解析失败**: `logger->error("命令执行参数解析失败: {}", e.what())`

### 不可恢复错误
- **服务端强制断开**: 
  - `logger->error("服务端命令断开连接 原因:"+msg)`
  - `logger->error("此错误具有不可容错性!请检查插件配置文件!")`
  - `logger->warning("正在断开连接...")`

## 重连机制

| 参数 | 值 | 说明 |
|------|-----|------|
| `maxReconnectCount` | 5 | 最大重连次数 |
| `reconnectCount` | 0 起始 | 当前重连次数 |
| 重连间隔 | 由 `setReconnectTask()` 控制 | 定时器控制 |

## 迁移建议

新代码 `HuhobotClientNew.cpp` 和 `WsConnectionManager` 中应参考以下改进：

### 紧急修复（协议合规性）

>  **新代码缺失 4 个官方协议定义的状态码**

| 缺失状态码 | 影响 | 修复优先级 |
|-----------|------|-----------|
| `4` - 版本不匹配 | 用户插件版本过低时无提示，可能持续重连失败 | **P0** |
| `5` - 尚未连接 | 可能误触发重连逻辑 | **P1** |
| `7` - IP 未授权 | 服务器 IP 变更时无法正确提示 | **P1** |
| `8` - 服务器被 Ban | 严重问题但无明确错误提示 | **P0** |

### 代码改进建议

1. **错误码枚举化**: 将魔法数字改为具名常量或枚举
2. **统一错误处理**: 建立统一的错误码体系和错误处理中间件
3. **错误恢复策略**: 区分可恢复错误和不可恢复错误
4. **错误上报**: 考虑增加错误上报机制，方便远程诊断

### 新代码修复示例

```cpp
void BotClient::handler_shaked(string packId, json &body) {
    int code = body["code"];
    string msg = body["msg"];
    
    switch (code) {
        case 1:  // 握手成功
            logger->info("与服务端握手成功.");
            shouldReconnect = true;
            isShaked = true;
            shakedProcess();
            break;
        case 2:  // 带有附加消息的握手成功
            logger->info("握手完成！附加消息:{}", msg);
            shouldReconnect = true;
            isShaked = true;
            shakedProcess();
            break;
        case 3:  // 客户端密钥不匹配
            logger->error("握手失败，客户端密钥错误，请检查配置文件.");
            shouldReconnect = false;
            isShaked = false;
            break;
        case 4:  // 客户端版本不匹配 [新增]
            logger->error("握手失败，插件版本不匹配，当前版本: {}，请升级插件.", HuHoBot::getVersion());
            shouldReconnect = false;
            isShaked = false;
            break;
        case 5:  // BotClient 尚未连接 [新增]
            logger->warning("服务端尚未准备好，等待连接...");
            // 不触发重连，等待服务端主动发起握手
            break;
        case 6:  // 等待绑定
            logger->info("与服务端握手成功，服务端等待绑定...");
            shouldReconnect = true;
            isShaked = true;
            shakedProcess();
            break;
        case 7:  // IP 未授权 [新增]
            logger->error("握手失败，当前 IP 未授权，请检查服务器网络配置.");
            shouldReconnect = false;
            isShaked = false;
            break;
        case 8:  // 服务器被 Ban [新增]
            logger->error("握手失败，服务器已被禁用，请联系 HuHoBot 管理员.");
            shouldReconnect = false;
            isShaked = false;
            break;
        default:  // 未知状态
            logger->error("握手失败，原因: {}", msg);
            shouldReconnect = false;
            isShaked = false;
    }
}
```

## 注意事项

- 错误码 `3`（密钥错误）是不可恢复的，需要用户干预
- 错误码 `6` 是特殊状态，表示握手成功但需要绑定确认
- 服务端强制断开（shutdown）具有不可容错性，必须停止重连
